# TrainBoard 开发文档

## 架构

| 模块 | 职责 |
|---|---|
| trainboard/config.py | 配置解析、路径基准、参数类型校验、argv 与环境变量生成 |
| trainboard/scheduler.py | 串行派发、队列持久化、日志采集、进程树停止 |
| trainboard/runs.py | CSV / JSONL 读取、字段别名、历史扫描、图片白名单 |
| trainboard/server.py | HTTP API、管理员与只读密钥、队列实例锁 |
| trainboard/static/ | 无外部 CDN 的 HTML、CSS、JavaScript |
| examples/train_demo.py | 可离线体验的 CPU 合成训练 |

启动方式为 `python -m trainboard`。项目按源码目录运行，无前端编译步骤。服务依赖 Python 标准库和 psutil。

## 任务协议

每次排队生成一个 12 位随机任务 ID，run 路径为 entry_id + 下划线 + ID。队列在创建任务时固定超参数，启动时按本次服务读取的入口配置生成 argv。自定义 argv 使用列表，Popen 的 shell 保持关闭。

运行目录生成 run.json，记录展示名和任务参数。训练程序可写 config.json 描述模型与配方。Scheduler 写 status.json，phase 为 completed、failed 或 stopped。队列 JSON 另外保留 created、started、ended、pid、pid_created、exit_code。

任务失败时暂停，恢复需用户操作。队列状态修改持有 RLock，并写临时文件后原子替换。HTTP 服务还持有平台文件锁。进程树在 Windows 使用 taskkill /T，在 POSIX 使用独立进程组及 SIGTERM，超时后 SIGKILL。

## 指标文件

推荐 metrics.jsonl 每行一个 JSON 字典。

```json
{"epoch": 1, "train_loss": 0.4, "valid_loss": 0.45, "accuracy": 0.82}
```

CSV 的首行是字段名。epoch 用于排序，同一 epoch 在多个文件出现时按 history.csv、epoch_metrics.csv、metrics.jsonl 的顺序合并。无法解析的 JSON 行和非有限数值跳过，以支持训练过程中尚未写完的一行。缺失指标保持为空。

primary_metric 取指定字段并按 metric_mode 找历史最优值。前端 API 中 auc 是兼容原面板的主指标槽位，实际字段名由 primary_metric 返回。前端指标下拉展示所有数值字段。

## 标准输出进度

```json
{"epoch": 1, "epochs": 8, "batch": 20, "batches": 100, "phase": "train"}
```

phase 可以为 train、valid、epoch_saved。detail 可以放人类可读状态。标准输出全部捕获，JSON 进度只是可选解析通道。训练脚本自行设置 flush=True 或使用无缓冲输出。

## HTTP API

所有 /api 请求均需 X-Panel-Token。GET 支持管理员或只读密钥。POST 需要管理员密钥，同源浏览器请求还检查 Origin。

| 方法与路径 | 输入或返回 |
|---|---|
| GET /api/catalog | 入口、参数、主指标、readonly |
| GET /api/state | enabled、current、message、jobs |
| GET /api/runs | 历史运行列表 |
| GET /api/run?id=... | 单次运行、指标序列、逐类数据和图片列表 |
| GET /api/log?id=... | 最后约 64 KiB 标准输出 |
| GET /api/source?id=... | 入口源码，仅管理员可读 |
| GET /api/guide | 使用说明文本 |
| GET /api/figure?id=...&name=... | 白名单中的运行图片 |
| POST /api/control | action、id、task |

控制动作支持 add、start、pause、up、down、remove、stop。

```json
{"action":"add","task":{"entry":"demo","epochs":4,"seed":42}}
```

失败返回 JSON error 和 HTTP 400/403/404。读取路径强制限制在 runs_dir，拒绝目录穿越和指向运行目录外的图片符号链接。

## 扩展与验证

增加新指标别名可修改 runs.py 的 ALIASES；增加可下载图类型可修改 FIGURES。增加任务参数优先使用配置。若要新增执行器或并行 GPU 调度，需要扩展调度器的资源与生命周期模型。

运行 `python -m unittest discover -s tests -v`。测试涵盖参数传递、JSONL 部分写入、目录边界、串行派发、失败暂停、重排、停止及 HTTP 读写权限。当前发布在 Windows 上完成验证。Linux / macOS 使用 POSIX 文件锁和进程组实现，接入时请在目标主机运行同一套测试。

对前端修改可运行 `node --check trainboard/static/app.js`，随后用 CPU 示例验证排队、日志、曲线和只读模式。
